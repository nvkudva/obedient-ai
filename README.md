# obedient-ai

A Claude Code plugin marketplace with two plugins, each switched on or off with `claude plugin disable <name>@obedient-ai` (and `enable`). `obedient-ai` injects standing rules into every session, an optional output style, guard hooks for dangerous git, foreground sleeps and `pip install`, and the `polish`, `learn-logs`, `marketing` and `post` skills. `token-saver` cuts token use with four parts, each with its own switch: `quick` runs short command prompts like `commit` or `run` without a main-model turn, `trim` stops wasteful Reads and repeat errors, `nudge` offers a fresh start on an unrelated task in a big session, and `cache` keeps the prompt cache warm (off by default, each ping spends tokens). They are for people who want Claude terse and cheap by default instead of repeating the same instructions each time.

It replaces keeping those rules in `~/.claude/CLAUDE.md`. Keep both and the same text loads twice per session.

## Requirements

- Claude Code, either the CLI or claude.ai cloud sessions
- A POSIX shell on PATH, plus `jq` for the guard hooks. On Windows without one, the hooks do nothing
- Git, if you install from a local clone
- macOS is the tested platform: `export-scratch.sh` builds a `/private/tmp` path, and token-saver downscales images with `sips`
- `tools/bootstrap.sh` is optional and does touch the network and your machine, see "Bootstrap script" below
- No accounts or keys

## Run it

```bash
claude plugin marketplace add nvkudva/obedient-ai
claude plugin install obedient-ai@obedient-ai
claude plugin install token-saver@obedient-ai      # optional: saves tokens (quick commands, trimmed reads, fresh-start nudge)
```

The marketplace holds two separate plugins; installing one does not install the other. Turn one off without uninstalling: `claude plugin disable token-saver@obedient-ai`. Inside a session, `/saver` shows what each part did, and `/saver off|on quick|trim|nudge|cache` switches one part; the choice is stored. The same four switches are plugin settings (`isQuickOn`, `isTrimOn`, `isNudgeOn`, `isCacheKeeperOn`). The Homebrew tools and settings merge come only from running `tools/bootstrap.sh` yourself.

From inside a session use `/plugin marketplace add nvkudva/obedient-ai` then `/plugin install obedient-ai@obedient-ai`.

From a local clone:

```bash
git clone https://github.com/nvkudva/obedient-ai.git
claude plugin marketplace add ./obedient-ai
```

On claude.ai: **Settings → Capabilities → Plugins → Add marketplace**, enter `nvkudva/obedient-ai`, then toggle **obedient-ai** on.

Start a new session and run `/plugin` or `claude plugin list`; obedient-ai should be listed as installed. Existing sessions need a restart.

## How it works

`dist/claude/obedient-ai/hooks/hooks.json` (generated by `tools/sync.py`) registers these hooks:

- `SessionStart`: asserts `${CLAUDE_PLUGIN_ROOT}/context/rules.md` is non-empty, then `cat`s it into the session context. A missing or empty file prints its path and exits 2, so a broken install fails loudly instead of starting a rule-free session.
- `SessionStart`: `hooks/export-scratch.sh` exports `$SCRATCH` (the session scratchpad path) and puts GNU `sed` and `timeout` first on PATH when Homebrew has them.
- `PreToolUse:Bash`: `block-dangerous-git.sh` blocks irreversible git and `rm` commands (list in `rules.md`, "Guardrails"). It is skipped in auto mode. Bypass one command with `ALLOW_DANGEROUS_GIT=1`.
- `PreToolUse:Bash`: `block-sleep.sh` blocks a foreground `sleep` over 10 seconds. Bypass with `ALLOW_SLEEP=1`.
- `PreToolUse:Bash`: `prefer-fast-tools.sh` blocks `pip install` when `uv` is installed. Bypass with `ALLOW_SLOW_TOOL=1`.


There is no per-project override. The reply format (short numbered bullets, superscript numbers, lettered options) lives in one file, `core/output-styles/mini.md`. In Claude Code it is an output style: select it with `/output-style` or `"outputStyle": "obedient-ai:mini"` in settings, and switch to any other style the same way. The OpenCode adapter injects the same file as plain rules. Keep no copy in `~/.claude/output-styles/`.

The rules payload is `core/context/rules.md`: working style, writing code, code and coding style, reading and searching, delegation, project memory (`AGENTS.md`/`PLAN.md`/`TODO.md`), session hygiene, efficiency, and guardrails and browser. It assumes tools such as `trash`, `rg`, `uv` and the `handoff` agent; edit `rules.md` to match your machine.

OpenCode uses the same `rules.md` plus a second file, `core/context/rules-opencode.md`, loaded by `dist/opencode/index.ts`. Anything that is only true in OpenCode lives there — tool names (`shell` not `bash`), background jobs, subagent names, and the fact that the git guard hooks do not run — so the shared `rules.md` stays valid in every harness.

Four rules, verbatim, so you can judge the fit before installing:

- "Edit, never rewrite. Use the smallest `old_string` that is still unique."
- "Run targeted tests — one file, one test — not the suite, unless I ask."
- "If you fail 3 times at the same problem, or keep repeating the same approach, stop and tell me what you tried."
- "Before a deploy or any production step, ask me once, up front, for the whole sequence. Then run it without further prompts."

## Bootstrap script

`tools/bootstrap.sh` runs only when you run it; no hook calls it. It installs Homebrew if missing (`curl | bash` of the official installer), runs `brew install` for 18 CLI tools the rules expect (ripgrep, fd, ast-grep, jq, yq, duckdb, sd, bun, watchexec, difftastic, jc, htmlq, scc, ruff, gitleaks, gnu-sed, coreutils, bash), then merges `tools/claude-settings.json` into `~/.claude/settings.json`: a read-only Bash allowlist, `CLAUDE_CODE_SHELL`, and an auto-compact window. Your existing keys win over ours, and the old file is saved as `~/.claude/settings.json.bak`. Do not run it if you do not want Homebrew packages installed.

The plugin also bundles four skills, each loaded lazily when its description matches the request:

- `polish` (`core/skills/polish/SKILL.md`) polishes any codebase without changing behavior: dead code removal, folder reorganization, file and function renames, test and doc tidy-up. It plans first, waits for approval, then commits one step at a time, following the code style rules in `rules.md`.
- `post` (`core/skills/post/SKILL.md`) drafts LinkedIn posts in the author's voice. Drop a `voice.md` at `~/.config/obedient-ai/voice.md` to replace the built-in persona; the post-structure rules still apply.
- `marketing` (`core/skills/marketing/SKILL.md`) analyses a project and builds a launch kit: a Remotion video (it first asks desktop 16:9, mobile 9:16 or both; desktop is the default), LinkedIn, X and Instagram posts, and a review-agent loop that iterates until the output is ship-quality. It needs Node and ffmpeg, and loads the separately installed `remotion-best-practices` skill.
- `learn-logs` (`core/skills/learn-logs/SKILL.md`) audits a coding agent's own session logs for failures, repeated calls, latency and wasted context. It ships two DuckDB adapters, `queries/opencode.sql` and `queries/claude-code.sql`, both run against real stores before shipping, and encodes the traps that produce wrong conclusions — turn wall clock masquerading as tool latency, the legacy `part` table truncating the window, and shell calls that exit non-zero while reporting `completed`. Needs `duckdb`.

| Claude Code | yes | yes | yes |
| Antigravity | yes, via `dist/antigravity/rules/AGENTS.md` (run `agy plugin install ./dist/antigravity`) | yes (`dist/antigravity/skills`, built from `core/skills`) | guard hooks yes (`PreToolUse` on `run_command`); `token-saver` no |

Edit only `core/`. Run `./tools/sync.py` after any change there: it rebuilds `dist/` (real files, not symlinks, because Claude Code copies a plugin to a cache and cannot follow links out of it). `tools/validate.sh` fails when they drift. `token-saver` uses Claude Code's `modules` / UI APIs and remain Claude-Code-only. In OpenCode and pi, the git, sleep and `pip` rules in `rules.md` are advice only.

## token-saver: trim and nudge

Part of the `token-saver` plugin, a Claude Code mod that warns before a session gets expensive and trims wasteful calls. Install with `claude plugin install token-saver@obedient-ai`, or try it from a clone with `claude --plugin-dir dist/claude/token-saver`.

- Status line shows context percent, cache time left, turns, calls and trimmed count; toasts at 150 turns and 300 calls (compact, or write a handoff and start fresh).
- A new, unrelated prompt in a session over 150k tokens asks whether to continue, start fresh or compact first.
- `cd dir && git …` is rewritten to `git -C dir …`.
- `Read` of a missing path is denied with a hint to run `rg --files` first.
- `Read` of a PNG or JPEG over 300 KB is downscaled with `sips -Z 1200` (macOS) and the smaller copy is read.
- `Read` of an unchanged file already read this session is denied; a changed modification time allows it. Passing `offset` or `limit` always allows it.
- `Read` of a file over 600 lines with no `offset` or `limit` is capped at 400 lines.
- The same tool error (digits ignored) three times in one turn appends a note to the third result telling the model to stop retrying and say what it tried. Once per turn, never blocks.
- `Bash` repeats and inline `python3 - <<` patch helpers raise a toast only; nothing is blocked.
- `/saver` prints the counters (kept across sessions) and the transcripts folder size.

Thresholds are constants at the top of `core/mods/token-saver/hooks/trim.ts`.

### cache

After `intervalMinutes` idle (default 55, for the 1-hour cache TTL) in a session over `minTokens` (150000) it sends a one-word ping up to `maxPings` times (2), then compacts. Each ping spends tokens, so it is off until you set `isCacheKeeperOn`. `/saver` shows how many pings and compactions it made.

## token-saver: quick

Part of the `token-saver` plugin: short command prompts run directly, with no main-model turn.

- Routes prompts of 6 words or fewer made only of command words and filler: `pull`, `commit`, `merge`, `push`, `release` (also `tag`, `bump`, `version`), `test`, `deploy`, `stop`, `restart`, `run` and combinations (`comit n psuh`, `commit push deploy`). Typos within one edit are matched. `prod` means deploy.
- `run`, `stop` and `restart` need a target (`run dev`, `stop all servers`, `restart dev server`); a bare `run it` or `stop` goes to the main model, since in past sessions those rarely meant the dev server.
- `pull` runs `git pull --ff-only`. `stop` stops only the server quickrun started for the project (the whole process tree); any other server is the main model's to find. `restart` is stop, then run.
- Paraphrases (`fire up the dev server`) go to the main model. An embedding match was tried and dropped: it caught 1 of 7,994 past prompts.
- A `?`, a question word, a work verb (`fix`, `add`, `explain`), a file path, or an action word next to an unknown one (`commit and version`) sends the prompt to the main model unchanged.
- `commit` stages everything (`git add -A`) and writes the message with Haiku (`commitModel`, through the session's own API client). Repo hooks such as pre-commit still run. Files that look like secrets (`.env`, `*.pem`, `*credentials*`) are unstaged and the prompt goes to the main model. Haiku takes about 0.8 s.
- `merge` fast-forwards the default branch to the current one, in the default branch's own worktree when it has one; anything else goes to the main model. `push` after `merge` pushes the default branch; otherwise it pushes the current branch and sets the upstream when missing.
- `run` and `test` pick the command from `.claude/quickrun.json`, then `package.json` scripts with the lockfile's tool, then commands learned from past sessions, then `manage.py`, `Cargo.toml`, `go.mod`, `pyproject.toml`. `run` starts detached, logs to `~/.claude/quickrun/logs/`, waits up to 4 s for a local URL, and reports the server it started earlier if that one is still alive.
- `release` picks the next version from the commits since the last `x.y.z` tag (breaking: major, or minor while 0.x; `feat`: minor; else patch), asks to confirm, bumps the first `version` field of tracked `*.json` and `*.toml` files that hold the current one (lockfiles skipped), commits `chore: release x.y.z`, adds an annotated tag with notes written by Haiku, and pushes the branch and the tag. Other places that name the version, such as a README line, are left alone.
- `deploy` runs only the `deploy` command in `.claude/quickrun.json`, after a confirm.
- A failed or unknown action hands the prompt to the main model with the error attached. When the main model then starts the server or runs the tests, that command is learned for the repo.
- What ran is told to the main model on your next prompt, since a handled prompt never enters the conversation.
- `/saver` shows the prompts handled and the main-model turns they replaced, priced at your past per-action averages.

Project config, all optional: `.claude/quickrun.json` with `{ "run": "bun run dev", "test": "bun test", "deploy": "./deploy.sh" }`.

`bun core/mods/token-saver/tools/history.ts eval` replays your transcripts and lists which past prompts would have been routed, with how often the main model did the same; `misses` lists the ones where it did something else; `seed` writes the run and test commands the main model used per repo to `~/.claude/quickrun/learned.json`.

## Layout

Edit only `core/`. `dist/` is generated by `tools/sync.py` and committed, because a GitHub install reads the repo as is. `tools/validate.sh` fails when `dist/` drifts from `core/`.

```
core/
  context/{rules,rules-opencode,rules-antigravity}.md
  output-styles/mini.md
  skills/{post,marketing,polish,learn-logs}/
  hooks/{_common,block-dangerous-git,block-sleep,prefer-fast-tools,export-scratch}.sh
  opencode/index.ts   the OpenCode adapter
  project.json        the only hand-written manifest facts: name, version, owner, repo, description, guard order
  mods/
    token-saver/ Claude Code only: plugin.json, hooks/{register,quick,trim,cache}.ts, tests, tools
dist/            generated, never edit
  claude/<plugin>/   what the marketplace installs (skills, rules and guard scripts copied in; tests left out)
  antigravity/  opencode/  pi/
tools/{sync.py,validate.sh,bootstrap.sh,plugin-usage.sh}, tools/claude-settings.json
.claude-plugin/marketplace.json
```

Adding an agent: one folder under `core/`, one block in `tools/sync.py`, one row in the table above.
